# The weekly system

How an episode turns into a week of clips without Tyler having to remember to start it or chase its progress. Confirmed by Tyler on 2026-11-11 unless marked untested.

## Timeline

1. **Recording lands in Riverside.** The full episode usually reaches YouTube 24 to 48 hours later. Use that window to prepare.
2. **Episode prep.** List the products and topics in the episode. Check the gear reference library for each product and fetch any missing verified photo once, for the whole episode.
3. **Fast two built and checked.** See below.
4. **Episode goes public on YouTube.** This is the trigger for posting. Check the channel `@fullstackcreatorshow` itself.
5. **Fast two posted** within 30 to 60 minutes of the episode going public.
6. **Best-of batch** built with Tyler and scheduled across the following week.
7. **Results logged** a few days after each post.

## Tier 1: the fast two

Purpose: clips up the same day as the episode, with almost no work from Tyler.

- Pick the two candidates most likely to be good on their own: a clear single point, a clean start, little cleanup risk.
- Build them fully and run the final checklist.
- A clip that fails any checklist item is held, and Tyler is told why. Post fewer rather than post a failed clip.
- Ask Tyler once per episode, showing both clips and their exact copy: "post these two when the episode is live?"
- After his yes, and only once the episode is confirmed public, post to Instagram, Facebook, TikTok and YouTube Shorts.
- His yes covers those two clips and that copy. If either changes materially, ask again.
- Inserts follow the fast-two rule in SKILL.md: verified real asset or no insert.

## Tier 2: the best-of batch

Purpose: the clips with the most potential, shaped by Tyler.

- Offer a longer candidate list with the transcript excerpt, draft hook and length for each.
- Tyler steers by number, typed or dictated. Do not wait on him for the fast two.
- Build, check, then hand off for review as one numbered list.
- Schedule approved clips at about two a day for the week after the episode.
- When a slot is open, a standout clip from an older episode can fill it. Search the transcript archive described in [brand](brand.md).

## One place to look

Each episode has one status file. Any assistant, on either Mac, reads it first and updates it last.

- Location: Tyler's Dropbox, `Documents/Full Stack Creator Podcast/06 Clip Jobs/<episode date and number>/status.md`
- Contents: the episode, whether it is public on YouTube, and for each clip its number, title, tier, Riverside edit, current revision, current export, state (candidate, building, held, ready for review, approved, scheduled, posted, killed) and what is waiting on Tyler.
- Keep private details here, not in the public skill repository.

Notify Tyler only when something is waiting on him. He prefers a phone notification.

## The feedback loop

- **Taste log:** `Documents/Full Stack Creator Podcast/06 Clip Jobs/taste-log.md`. One line per decision: date, episode, clip, what Tyler said (picked, killed, fix note in his words), and later the view counts per platform.
- Read the taste log before choosing topics for any episode, for both tiers.
- Riverside reports view counts for posted clips. Record them once a post has had a few days.
- View counts vary enormously between similar clips. Treat one result as an anecdote and look for patterns across many.
- Once a month, propose changes to this skill based on the log. A proposal becomes a rule only when Tyler confirms it.

## Previewing clips (untested)

Riverside gives no playable link for an export, only a link into its editor, and those links have not opened reliably for Tyler.

- Until a better route is proven, tell Tyler the studio, project and exact edit title so he can find the clip in the Riverside app.
- Candidate to test: post the clip to YouTube as unlisted and send that link, which opens on phone and Mac. Unlisted copies need clearing out of YouTube Studio by hand. Test on one clip, with Tyler's yes, before relying on it.

## Native posting (untested experiment)

The idea: captions and hooks added with a platform's own tools may perform better than ones burned in by an editor.

- If a phone that can run the platform's app is available to the assistant, export the clip without burned-in captions or hook and add them in the app, starting with TikTok.
- If no such phone is available, post through Riverside as usual. The routine must never depend on the phone.
- Tyler approves each native post on the final screen.
- Compare several native posts with several Riverside-captioned posts before drawing a conclusion.
