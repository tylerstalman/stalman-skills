# Clip Tyler's main YouTube channel

Read [the shared clipping core](../short-form-video-core/SKILL.md), then this channel's [brand profile](references/brand-profile.json). Do not load the podcast skill for styling. This workflow shares craft and authenticity lessons with the podcast, not Full Stack Creator's brand, accounts, participant layouts or Riverside tools.

## Start from the actual source

Use the current video brief and identify the exact approved master or editable source project. Prefer a high-quality local master over a downloaded platform copy when available. Preserve source frame rate, audio sync and intended color handling. Finished masters already contain baked cuts, music, graphics and possibly captions; inspect those before cropping or adding another treatment. A flattened render cannot restore hidden camera angles, separate audio stems or cropped-out pixels.

Build self-contained clips around an insight, demonstration, result or useful recommendation. Let this video's direction determine hook, pacing, length and coverage. The podcast's guest/reaction rhythm and one-to-two-minute estimate are not defaults here. Single-speaker clips are natural. Keep relevant original B-roll and overhead actions, including enough setup/result to understand them. Consider portrait, a purposeful layout showing the full demo, or another requested ratio from the actual footage; don't crop away the point merely to fill 9:16.

Avoid unsupported comparative claims, sponsors/affiliate obligations lost in trimming, and duplicate baked captions. Handle commercial passages according to the actual brief; do not infer permission to remove required disclosures. Apply the shared no-gaze-correction and exact-product rules.

## Choose one editing backend per clip

Read [backend selection](references/editing-backends.md) when choosing Final Cut or Resolve. Use the editable Final Cut project when original angles, layers, stems or editorial continuity matter. For batches cut from finished masters, Resolve scripting is the proposed default to pilot, not a proven cost winner. Verify the required controls in the current API and inspect the native output. Keep the plan editor-independent so a backend can change without redoing editorial analysis; avoid routine cross-app round trips.

For substantial edits inside an original Final Cut library, use the installed `final-cut-youtube-editing` skill for library, shared-compound, media and camera-specific guidance. That existing long-form skill remains intact; load only the relevant references. If it is unavailable, report the missing mechanics and preserve the source project rather than inventing an equivalent workflow.

Keep the long-form source edit unchanged. Create the requested short-form deliverable timeline(s) in the appropriate existing library/project, reusing original media and shared sources. Those requested deliverables are distinct outputs, not permission to accumulate test libraries or alternate copies of the long-form edit.
